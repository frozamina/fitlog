## 2. 产品定位与已确认需求

服集 FitLog（原名 FitLog）是用户自用、以本地数据为主的 Android 衣橱应用。它由原有衣物尺码/身体数据记录功能出发，吸收 Closet Kit 的电子衣橱、成套搭配与配色灵感。关键使用场景：**用户已经决定穿某一件衣服，希望从已有衣物中找到如何搭配**。

| 主题 | 决策与边界 |
|---|---|
| 基础 | 以现有 FitLog 原生 Android 为主体继续开发，整合衣橱能力，不要另起一套互不相通的衣物库。 |
| 最重要的流程 | 从一件已有衣物出发，推荐或选择其他单品，可替换单品，保存整套穿搭，之后能查看和修改。 |
| 保留 | 原有衣物档案、尺码/自定义属性、合身评价、图片、身体数据与历史记录、模板，以及完整数据备份/恢复。身体数据历史与每日穿着日记不是同一回事。 |
| 不作为当前需求 | 用户认为每日穿搭记录暂不实用，当前不做每日记录/日历；搭配收藏不绑定穿着日期。未来若需求改变，以用户最新要求为准。 |
| 配色 | 参考两款衣橱项目的配色功能和灵感；从真实衣物出发提供可解释的配色参考。 |
| 使用门槛 | 衣物照片、尺码可逐步补充；整合版说明中为选填。 |
| 平台与隐私 | Android 优先，当前本地优先、无账号、无联网；任何云同步、在线 AI 或上传照片都需要先明确需求和隐私影响。 |

过去曾讨论图片识别、去背景、天气、AI 等方向，但**没有依据表明这些都已确认进入当前版本**。如要纳入，应作为后续建议单独与用户讨论；尤其不要擅自把每日穿搭日记恢复为需求。

## 5. 目前实现与数据边界

### 整合版已实现（当前源码及此前自动测试）

- 统一衣物资料，纳入尺码、照片、颜色、图案、版型等；尺寸与照片可后补。
- 主导航为衣橱、搭配、灵感；从选定单品发起搭配、查看建议、替换/添加其他衣物、命名保存、编辑或另存。
- 可浏览配色灵感，并按主色相近筛选衣物；保留原有身体数据历史、衣物属性模板、照片、尺码相关能力。
- 配色推荐当前是本地启发式规则，不是 AI 视觉识别：`Styling.kt` 将颜色转换为 HSL，按中性色、色相、图案等规则排序。缺色值时提示不确定；不应宣传为智能识图、准确审美评分或合身保证。
- 身材/尺码对比应考虑单位和测量口径；测量口径不明、不同或单位无法换算时只并排展示，不应输出误导性的差值。
- Room 数据库版本为 2，存在 `MIGRATION_1_2`；备份结构支持 v2，并为旧 v1 图片绝对路径提供导入适配。导入采用追加策略，会生成新关联；重复导入可能产生重复记录。

### 两个安装包不能混为一谈

旧版源码基线的 applicationId 是 `com.fitlog.app`；预览版是 `com.fitlog.app.preview`，因此有独立数据。预览版不会自动看到旧版衣橱，也不会自动同步回旧版。安全迁移路径通常是旧版导出备份、预览版导入并核对，但用户当前实际迁移状态未知。

如需让新 APK **覆盖旧版**：需核实设备上的实际包名、版本号和原签名，并确保新包使用 Android 认可的同一签名身份、版本号满足系统更新要求；必须进行真实设备验证。当前已知签名与版本不构成对用户手机的验证。签名不匹配或确认前，**不要卸载旧版、清空数据或建议先删除旧版重装**。本项目数据为本地存储，此类操作可能丢失数据。

## 7. 代码地图与开发方法

- `app/src/main/java/com/fitlog/app/MainActivity.kt`：入口和导航。
- `data/Entities.kt`、`Dao.kt`、`Database.kt`、`Repository.kt`：Room 实体、数据访问、数据库迁移、业务数据操作。
- `data/Styling.kt`：离线配色/组合规则与尺码比较逻辑。
- `data/Backup.kt`、`util/BackupManager.kt`、`util/ImageStore.kt`：备份模型、ZIP 与图片存储。
- `ui/screens/StudioScreens.kt`、`StudioComponents.kt`：衣橱、搭配、灵感相关 UI；其他 `ui/screens` 包含原有详情、编辑、设置等。
- `ui/theme/`：颜色、样式及设计 token；`vm/AppViewModel.kt`：界面状态与仓库协调。
- `app/src/test/java/com/fitlog/app/`：`NativeIntegrationTest.kt`、`StylingTest.kt`、`StudioUiTest.kt`。
- `docs/整合版说明.md`：整合版功能、安装与数据说明；`docs/README-使用说明.md` 和旧 PRD 主要描述旧版，存在历史差异。

技术栈：Kotlin、Jetpack Compose、Room、kotlinx.serialization；最低 Android 8.0/API 26，compileSdk/targetSdk 34。整合版构建环境为 JDK 17、Android SDK Platform 34、Build Tools 34.0.0，Gradle Wrapper 在整合版中存在。主仓库 `main` 的 Wrapper 情况请以当前实际文件为准。

```bash
git clone https://github.com/frozamina/fitlog.git
cd fitlog
git fetch origin
git checkout main
git pull --ff-only origin main
./gradlew :app:testDebugUnitTest
./gradlew :app:assemblePreview
```

仅在本机具有 Android SDK、JDK 及依赖可用时执行。以默认 main 为当前入口，先检查远端和本地未提交修改。输出通常在 `app/build/outputs/apk/preview/`；确认实际路径。若工程或构建脚本发生变化，以当前仓库为准。不要把交接文件写死的临时工具目录当作长期环境。
