# 产品需求文档（PRD）
## 衣柜尺码助手（暂定名：FitLog 衣码记录）

| 项目 | 内容 |
|---|---|
| 文档版本 | V0.1（草案，待确认） |
| 平台 | Android APK |
| 文档日期 | 2026-10-12 |
| 目标用户 | 本人单机使用（本地优先，无需联网/无账号体系） |

---

## 1. 产品概述

### 1.1 背景与目标
网购/线下购买衣服时，不同品牌、不同版型的尺码标准不一致（同是 L 码，胸围衣长可能差异很大），导致买回来不合身。

本产品通过记录「我自己的身体数据」+「每件已购衣服的实际尺码与三维数据」，形成个人专属的尺码参考库，下次购买时快速对照，买到更合身的衣服。

### 1.2 核心价值
- 一次记录，长期复用：按品牌/版型查询"上次买的那件合身的衣服是什么尺码、什么数据"。
- 身体数据变化可追踪：体重变化后可回顾历史身体数据。
- 图片辅助记忆：看到商品图即可关联到已购同款/类似版型。

### 1.3 非目标（本期不做）
- 不做购物推荐、比价、电商对接。
- 不做云端同步、多用户、社交分享（预留后续扩展）。
- 不做 iOS / Web 版。

---

## 2. 用户画像与使用场景

**用户**：本人（单用户）。

**典型场景**：
1. 刚收到一件新买的上衣，量了衣长 68cm、胸围 106cm、肩宽 45cm，打开 App 记录，附上照片，标记"合身/偏大/偏小"。
2. 下次在店铺看到一件类似版型的外套，打开 App 搜索"外套"，找到之前合身的那件，对照尺码数据选购。
3. 体重变化后更新主页的身体数据，历史记录保留。

## 3. 功能需求

### 3.1 模块结构

```
主页面（我的身体数据）
├── 衣物列表页（全部记录 / 按类型筛选 / 搜索）
│   ├── 新增衣物记录
│   └── 衣物详情页（查看/编辑/删除）
└── 设置（数据备份导出、自定义属性模板管理）
```

### 3.2 功能明细

#### F1 主页面 —— 身体数据
| 项目 | 说明 |
|---|---|
| 记录字段 | 身高（cm）、体重（kg）、净胸围、净腰围、净臀围、肩宽、可选：领围/臂长/腿长等 |
| 操作 | 查看、编辑、保存 |
| 历史记录 | 每次修改保存一条带日期的历史快照，可查看身体数据变化趋势（简单列表即可，图表可选） |
| 展示 | 卡片式展示当前身体数据；显示"上次更新时间" |

#### F2 衣物记录 —— 新增/编辑
| 项目 | 说明 |
|---|---|
| 基本信息 | 衣物名称、购买品牌（可选）、购买日期（可选）、购买渠道备注（可选）、价格（可选） |
| 衣物类型 | 上衣 / 背心 / 裤子 / 高弹短裤 / 外套 / 内裤 / 帽子（可扩展），选择类型后自动带出对应默认属性模板 |
| 尺码标签 | 该件衣服的标码（如 S/M/L/170/96A/29/31 等，文本输入） |
| 三维属性 | 根据类型带出默认属性，数值单位 cm（裤子腰围可选"尺码"单位如 29/30）：<br>· 上衣：衣长、胸围、肩宽<br>· 背心：衣长、胸围、肩宽<br>· 裤子：裤长、腰围、臀围、前裆/后裆（可选填）<br>· 高弹短裤：裤长、腰围、臀围<br>· 外套：衣长、胸围、肩宽<br>· 内裤：腰围、臀围<br>· 帽子：头围、帽檐长（可选填） |
| 自定义属性 | 支持"添加自定义属性"：属性名 + 数值（+可选单位），任意数量；可保存为该类型的模板属性，下次自动带出 |
| 合身评价 | 单选：紧身 / 合身 / 宽松（三档）（+ 可选文字备注，如"袖子偏长，下次选短袖版"） |
| 图片 | 支持从相册选择 / 拍照上传，最多 9 张，本地存储，可设置 1 张为封面 |
| 保存 | 必填项仅：名称、类型、至少 1 个尺码属性；其余均可留空 |

#### F3 衣物列表页
| 项目 | 说明 |
|---|---|
| 展示 | 卡片列表：封面缩略图 + 名称 + 类型 + 标码 + 合身评价标签 |
| 筛选 | 按类型（上衣/裤子/…）、按合身评价筛选 |
| 搜索 | 按名称/品牌关键字搜索 |
| 排序 | 默认按添加时间倒序 |
| 操作 | 点击进入详情；左滑删除（二次确认） |

#### F4 衣物详情页
- 大图浏览（可左右滑动查看所有图片）。
- 完整属性表展示。
- 编辑、复制为新记录（用于买同款第二件时快速记录）、删除。

#### F5 设置
- **数据导出/备份**：导出为 JSON 文件（含图片打包 zip）到本地存储；支持导入恢复。
- **属性模板管理**：查看/编辑各衣物类型的默认属性与自定义属性模板。
- 关于/版本信息。

### 3.3 原型示意（文字线框）

```
┌─────────────────────────┐
│  我的身体数据             │
│  身高 175cm  体重 68kg   │
│  胸围 96   腰围 78 ...   │

└─────────────────────────┘
```

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 运行环境 | Android 8.0（API 26）及以上 |
| 数据存储 | 本地优先：SQLite（结构化数据）+ 本地文件（图片）；无需联网 |
| 隐私 | 所有数据仅存本机，无任何上传 |
| 性能 | 列表滚动流畅；图片压缩存储（长边 ≤ 1600px） |
| 备份 | 手动导出/导入 JSON+图片压缩包 |

---

## 5. 数据模型（草案）

```
BodyProfile  身体数据快照：id, date, height, weight, chest, waist, hip, shoulder, extra(JSON)

Garment      衣物：id, name, type, brand, sizeLabel, fitRating(合身/偏大/偏小),
             purchaseDate, channel, price, note, coverImageId, createdAt

GarmentAttr  衣物属性：id, garmentId, attrName, attrValue, unit, isCustom, sortOrder

GarmentImage 图片：id, garmentId, filePath, isCover, sortOrder
```

## 6. 里程碑（建议）

| 阶段 | 内容 |
|---|---|
| M1 | 身体数据页 + 衣物增删改查（默认属性）+ 列表 |
| M2 | 自定义属性 + 图片上传 + 筛选搜索 |
| M3 | 合身评价、复制记录、数据导出导入、打磨 UI |

---

## 7. 已确认决策

1. **衣物类型**：上衣 / 背心 / 裤子 / 高弹短裤 / 外套 / 内裤 / 帽子（不含裙子、鞋）。
2. **默认属性**：上衣、背心=衣长/胸围/肩宽；裤子、高弹短裤=裤长/腰围/臀围（裤子的前裆/后裆可选）；内裤=腰围/臀围；帽子=头围/帽檐长。袖长、大腿围不作为默认，可按需自定义添加。
3. **合身评价**：紧身 / 合身 / 宽松（三档）。
4. **技术栈**（已决策）：原生 Android，Kotlin + Jetpack Compose + Room(SQLite)。理由：单平台单用户，原生 APK 最小、启动快、无跨端框架开销；本地存储与相机/相册能力原生最成熟。
5. **历史身体数据**：M1 用列表快照，图表趋势放 M3 可选。
